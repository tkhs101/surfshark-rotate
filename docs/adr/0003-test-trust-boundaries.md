# ADR 0003：测试的可信边界 —— 绿灯不等于验证过

Status: implemented（2026-10-09）

## 背景

三轮评审里反复出现同一类问题，而且它一次比一次隐蔽：

**同义反复。** `test_three_cases_are_mutually_exclusive` 构造一个字典，
在**自己抄的** `if/elif` 链上断言抄对了，整个函数体不读被测文件。
把 `install.sh` 的三段判据整个删掉，它照样绿。

**从未执行。** 一个测试类被追加到文件末尾，而文件末尾是
`if __name__ == "__main__": unittest.main()`。类定义发生在 runner 调用之后，
收集时根本不存在。比同义反复更隐蔽 —— 连 `FAILED` 都不会有。

**套件整体没运行。** 删除重复测试类时把那个 `__main__` 块一起删掉了。
`python3 tests/test_rotate.py` 变成 **exit=0、零字节输出**。
而我的检查方式恰恰是「exit=0 且 `grep -c FAILED` 为 0」——
两个条件在「套件没跑」时**同时成立**。我把这个假绿灯写进了提交信息。

三次的共同点：**检查手段与被检查对象共享同一个失效模式。**
前两次还能靠「注入破坏看它变不变红」发现；第三次连这个都不行 ——
注入破坏时套件也没在跑。

## Decision

三条，按能否被套件内部发现排列：

**一、写测试时必须注入一次真实破坏，确认它会红。** 这条无法机械化 ——
它是一个动作习惯，不是状态。已在提交信息与代码注释里反复记录，
因为本项目三次都是靠这一步发现的，也三次都是因为**没做这一步**而漏掉。

**二、测试替身的猴补丁必须用 `addCleanup` 还原。**
`RotateTestBase.patch(obj, name, value)` 是唯一入口。
直接 `r.foo = lambda` 会永久改掉模块属性，而测试之间共享同一个模块实例，
补丁会漏到后面的测试类里 —— 已实测发生过：`TestDegradeCorroboration`
把 `pick_next` 打成 lambda 且从不还原，导致后面新写的轮询测试
是在**被污染的模块**上跑的。

**三、跑测试用 `tests/run.sh`，不用裸 `python3 tests/test_rotate.py`。**
它断言输出里有 `Ran N tests`，而不只是退出码。

第三条是关键：**runner 丢失时套件内部的任何测试都不会运行，
因此不可能失败。** 套件内部没有任何测试能察觉这件事。
防线必须放在套件外面。

## Alternatives considered

**只用 `pytest`。** 它有更好的失败输出和内建的「收集到 0 个测试」警告
（`pytest` 对空收集会报错，而 `unittest` 不会），能直接堵住第三类事故。
不采用的理由是这个项目长期用 `unittest` + 标准库，换过来的收益
不足以抵消「114 个用例要重写断言风格」的改动量。**这是一个明确的取舍，
不是「不知道有 pytest」。**

**给测试文件加一个哨兵，检测自己没被运行。** 考虑过在文件顶部写一个
`atexit` 钩子，未运行时不产生任何效果 —— 无运行即无钩子，这个想法自相矛盾。

**把「跑测试」收进 CI，只看 CI 的绿灯。** CI 是好的第二道防线，
但本项目是单机部署、没有 CI。`tests/run.sh` 能在本地做同样的事，
且不引入 CI 依赖。

## Consequences

**收益**：第三类事故（套件没跑）现在会明确失败并说明原因。
第一类（同义反复）靠注入破坏这个动作挡住，但那个动作仍然是人做的。

**代价**：`tests/run.sh` 的存在本身需要被记住 ——
新人直接 `python3 tests/test_rotate.py` 就绕过了它。
缓解手段是在提交信息与本 ADR 里都写明，但没有强制机制。

**仍然存在的漏洞**：
- 同义反复只有靠注入破坏发现，没有静态手段能保证测试真的读了被测对象。
- 新的替身（helper、fixture）可能绕过 `patch()` 直接赋值。
  已加 `TestRunnerOrder` 类的「声明的类都被收集」测试作为粗筛，但不是全覆盖。
